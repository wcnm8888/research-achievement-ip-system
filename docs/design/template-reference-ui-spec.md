# 模板参考型 UI 重构：视觉规格与页面骨架

> 阶段：阶段一——模板视觉规格提取与页面骨架定义
> 状态：规格草案，待工作台视觉方向确认后进入实现
> 日期：2026-07-28

## 1. 目标与边界

本规格用于指导后续的“模板参考型 UI 重构”。目标不是复制 Energy Management System Dashboard 的业务页面，而是借鉴其信息组织方式，把本项目改造成具有明确层级、数据节奏和操作重点的科研成果管理工作台。

本阶段不修改业务代码、API、权限、数据模型、数据库或 Figma 文件。

保留范围：

- 现有 React + Ant Design 技术栈；
- 现有 API 调用和返回字段；
- 现有角色、权限边界和无权限行为；
- 现有成果、审批、费用、提醒和配置业务逻辑；
- 现有统一图标来源和状态组件能力。

## 3. 模板视觉规则提取

### 3.1 页面层级

模板形成了比较稳定的阅读路径：

```text
固定应用侧栏
    ↓
页面标题 / 欢迎信息 / 系统状态
    ↓
横向筛选和范围控制
    ↓
关键指标卡
    ↓
两列或多列业务面板
    ↓
趋势、明细或辅助说明
```

适配到本项目后，能源设备、能耗和环境指标替换为科研成果、审批、费用和档案状态；布局关系保留，业务语义不复制。

### 3.2 颜色关系

模板不是单一绿色页面，而是通过以下关系形成层级：

- 深色侧栏承载导航和品牌身份；
- 明亮强调色表示当前导航、主要动作或实时状态；
- 低饱和浅色承载筛选区、辅助信息和状态背景；
- 白色面板承载主要内容；
- 绿色、蓝色、琥珀色和红色分别表达不同业务语义；
- 大面积区域避免使用强渐变；
- 颜色用于区分层级和状态，不替代文字。

### 3.3 字体与信息密度

- 页面标题明显高于区块标题，但不采用营销型超大标题；
- 指标数字使用较大字号和稳定的数字对齐；
- 标签、单位、时间和辅助说明使用较低对比度；
- 业务名称保持清晰，技术编号和日期允许使用等宽数字；
- 内容密度高于展示型网站，但通过留白和分组避免拥挤。

### 3.4 组件表达

模板可复用的组件关系包括：

- 品牌区和固定侧栏；
- 侧栏中的图标 + 文本导航项；
- 页面标题和右侧状态/操作；
- 横向筛选工具栏；
- 指标卡；
- 统一面板标题；
- 状态标签；
- 进度条或比例表达；
- 空间充足的白色内容面板；
- 移动端折叠或单列内容。

## 5. 项目统一页面骨架

### 5.1 应用外壳

```text
AppShell
├── AppHeader
│   ├── BrandMark
│   ├── ProductName
│   ├── Environment / Identity
│   └── AccountAction
├── PrimarySidebar
│   ├── CurrentUserSummary
│   └── NavItem(icon + label + active state)
├── MobilePrimaryNav
└── MainContent
    └── PageFrame
```

规则：

- 桌面端保留左侧导航；
- 平板端压缩内容间距，避免导航挤压主区域；
- 移动端使用现有移动导航策略，页面内容改为单列；
- 导航图标统一使用现有 Ant Design 图标组件，不使用文字字符模拟图标；
- 当前项通过背景、文字和图标同时表达，不只依赖颜色。

### 5.2 页面级骨架

```text
PageFrame
├── PageHeader
│   ├── Breadcrumb / Context
│   ├── Title
│   ├── Description
│   ├── Status
│   └── PrimaryActions
├── ScopeToolbar / FilterToolbar
├── SummaryRegion (可选)
├── MainRegion
└── SecondaryRegion / DetailRegion
```

页面不再默认采用“标题 + 多个同级 Card 纵向堆叠”。每个页面必须先确定首要任务、主数据区域和辅助信息区域。

## 6. 五个核心页面骨架

### 6.1 工作台

```text
工作台标题 + 系统状态 + 刷新
        ↓
数据范围 / 时间范围 / 当前身份
        ↓
关键指标：成果总量 | 待处理审批 | 费用风险 | 近期到期
        ↓
待办审批（主列） | 最近成果（辅助列）
        ↓
提醒、快捷入口或趋势摘要
```

重点：待办优先，指标服务于决策；不能用无意义的统计卡填满首屏。

### 6.2 成果列表

```text
成果列表标题 + 新增成果
        ↓
关键词 / 类型 / 状态 / 负责人 / 时间范围
        ↓
当前范围与数量摘要
        ↓
成果表格：身份信息 | 类型 | 负责人 | 更新时间 | 状态 | 操作
```

重点：筛选和新增动作明确，表格按档案信息组织，技术编号使用等宽字体，操作列保持稳定宽度。

### 6.3 成果详情 / 编辑

```text
成果身份标题 + 编号 + 当前状态 + 操作
        ↓
主体信息面板                 审批/版本侧栏
├── 基础信息                  ├── 当前状态
├── 关键词和摘要              ├── 提交人
├── 附件和关联信息            ├── 版本记录
└── 编辑字段                  └── 操作说明
```

重点：只读信息、可编辑字段和审批状态分层，不能把所有内容放进一个长表单。

### 6.4 审批任务

```text
审批任务标题 + 范围状态
        ↓
待我审批 | 我发起的 | 已处理
        ↓
任务筛选工具栏
        ↓
任务列表：任务 | 成果/费用 | 优先级 | 截止时间 | 状态
        ↓
详情抽屉：上下文、允许动作、必填意见、完成反馈
```

### 6.5 系统配置

```text
系统配置标题 + 权限/运行状态
        ↓
配置目录       当前配置面板
├── 组织与权限   ├── 当前组织
├── 成果类型     ├── 默认角色
├── 审批规则     ├── 数据范围
├── 通知提醒     ├── 开关和参数
└── 数据字典     └── 保存 / 校验 / 历史
```

重点：配置导航与配置内容分栏；敏感信息只显示脱敏摘要或状态，不展示完整 Token、密码、Cookie、私钥或连接串。

## 7. 第一阶段的实现前置约束

进入工作台实现前，必须先确认：

- 工作台采用“筛选范围 → 指标摘要 → 待办/最近成果”的主结构；
- 主列与辅助列的比例；
- 指标卡是否采用深色信息卡，及其状态色规则；
- 侧栏深色、当前项浅色高亮的关系；
- 页面背景、面板背景和边界对比度；
- 桌面、平板和移动端的折叠顺序；
- 统一图标和按钮规格；
- 正常、loading、空、错误、无权限、提交中和成功状态的布局位置。

## 8. 必须在 Figma 中确认的内容

以下内容不能只依据截图或推测，应在 Figma 中确认后再固化：

1. 模板实际使用的字体族和字重；
2. 主色、强调色、页面背景和状态色的精确 HEX/RGB；
3. 侧栏宽度、内容最大宽度和页面边距；
4. 指标卡的高度、内边距和圆角；
5. 筛选控件的高度、间距和按钮宽度；
6. 面板阴影的真实层级；
7. 移动端侧栏转换方式和导航交互；
8. 模板中哪些组件是可复用结构，哪些只是能源业务专属展示。

确认方式：选中 Figma 图层查看 Inspect/变量/样式信息，并将确认后的值回填到项目 Token 表；不创建或修改模板文件。
