更新时间：2026-07-26

本文档描述当前源码已经形成的 UI 结构和状态约定。它不是尚未实现的视觉原型，也不把自动化测试结果写成浏览器视觉验收结果。

## 应用外壳

- 顶部区域展示产品名称、当前身份和环境边界；开发模式可显示 demo 身份控制，生产构建使用登录会话。

## 组件和状态规则

- 统计卡片用于少量核心指标，不承载复杂编辑。
- 表格用于可筛选、可排序或需要对比的记录；窄屏需要允许横向滚动或转为卡片信息。
- 卡片用于信息分组、摘要和空状态承载。
- 抽屉用于详情、审批或不应打断主列表的编辑流程。
- 表单必须提供字段标签、校验反馈、提交中状态和失败反馈。
- `apps/web/src/components/StateBlocks.tsx` 提供通用的数据加载、错误、空数据、权限提示和边界提示。

| 状态 | 当前 UI 要求 |
| --- | --- |
| 加载 | 显示明确的加载状态，避免把尚未返回的数据当作空数据 |
| 空数据 | 说明当前范围没有记录，并在适用时给出创建、导入或调整筛选入口 |
| 错误 | 展示可理解的失败原因和重试入口；不展示完整堆栈 |
| 未登录/无权限 | 区分登录失效和权限不足，不暴露资源敏感细节 |
| 成功 | 使用短暂提示或页面内反馈，说明动作已完成 |
| 网络中断 | 保留用户输入，允许安全重试，避免重复提交 |

## 响应式行为

当前主要断点为 `960px` 和 `640px`：

- 宽度不超过 960px 时收缩桌面布局、减少并排列数，并提高内容区域可用宽度。
- 宽度不超过 640px 时使用单列内容、横向导航和可滚动表格；表单字段优先纵向排列。
- 这些断点来自当前 CSS 实现，不代表已经完成所有设备上的人工视觉验收。

## 页面状态边界

登录页、工作台、成果、审批、费用、提醒、检索、看板、报表、审计、系统配置、涉密授权、账号和部门页面均已有对应页面入口或组件。当前测试能够覆盖部分数据、交互和权限状态，但以下事项仍需浏览器专项验收：

- 首次加载、无数据、接口失败、无权限和成功反馈在不同页面的一致性。
- 桌面宽屏、约 1024px 平板宽度和约 390px 移动宽度。
- 表格横向滚动、抽屉开关、表单校验、上传/下载和长文本。
- 生产构建登录后的身份区、退出和会话失效展示。

## 安全展示边界

UI 不得显示密码、Token、Cookie、私钥、真实连接串、原始敏感字段或完整错误堆栈。涉密数据、附件和审计信息必须根据权限显示摘要或脱敏内容。

## 正式设计基线（阶段六评审结果：规格和方向已确认）

本节把 `E:\Vibe coding\references\UI` 中的四组方法提炼为本项目的可执行设计规则：先积累真实参考，再建立完整 Style/Design System；先设计用户完成任务的方式，再设计视觉；通过截图和精确参数持续较真；每个功能先定义状态和验收，再进入实现。本节是已确认的设计基线，不代表已经完成 UI 重构或浏览器视觉验收。

### 产品与用户场景

- 产品类型：研究院内部的科研成果与知识产权管理工作台。
- 主要用户：科研人员、科研秘书、部门管理员、主管/院领导、涉密成果管理员、内审人员、系统管理员。
- 高频任务：登记成果、补充附件、提交审批、处理部门任务、跟踪费用截止日期、检索成果、查看统计、审计操作。
- 设计优先级：可理解的任务状态 > 权限边界清楚 > 高密度信息可读 > 操作反馈及时 > 视觉装饰。
- 设备优先级：桌面端完成主要工作，平板端支持查看和轻量处理，移动端保证导航、查询、提醒和关键审批信息可用；一期不承诺完整移动端。

### 参考提炼与视觉方向

推荐方向：**冷静的科研档案工作台**。

- 气质：克制、可信、可追溯、适合长时间处理表格和审批任务。
- 装饰强度：minimal/intentional，以排版、层级、状态色和细边界形成秩序，不使用渐变主按钮、紫色渐变、装饰性大插画或营销化文案。
- 布局：grid-disciplined，桌面端使用稳定的侧栏、工具栏、内容网格和详情区域；只在工作台摘要区域使用有限的编辑性层次。
- 颜色：restrained/balanced，蓝青色作为行动和当前导航的信号，语义色只表达成功、警告、错误和权限风险，不用颜色代替文字。
- 参考使用规则：参考产品只用于提炼信息架构、密度、表格、状态和交互模式；不复制品牌、文案或未经确认的页面能力。用户已确认本方向，独立浏览器视觉表现仍需通过验收验证。

### UX 基线：先让用户完成任务

1. 每个页面先回答“我现在在哪、要完成什么、下一步能做什么、当前状态是什么”。
2. 工作台以待办和风险优先，不用无意义的统计卡片填满首屏。
3. 列表页先提供范围、筛选、搜索和批量阅读能力，再提供创建或处理入口。
4. 详情页必须能看清成果身份、密级、所属部门、当前状态、关键时间、附件和审计关联；编辑动作与只读信息分层。
5. 审批动作必须显示当前任务、提交人、数据范围、允许动作、必填意见和完成反馈，禁止只用颜色或图标表达权限。
6. 表单先分组再分步，保存草稿、提交审批和取消操作必须有明确区别；重复提交和网络失败要可安全重试。
7. 无权限、无数据、接口失败和服务不可用是产品状态，不是空白页面；提示要说明原因和可行的下一步，但不得暴露敏感细节。
8. 关键写操作完成后，要能从页面反馈、状态变化或审计入口确认结果，不依赖 AI 自述“已成功”。

### Style/Design System 候选

以下值以当前源码已使用的 token 为起点，Step 2 只形成规范，不在本 Step 修改 CSS 或组件代码。

| 类别 | 推荐基线 | 使用规则 |
| --- | --- | --- |
| 页面背景 | `#f4f6f8` | 作为工作区底色，避免大面积纯白造成层级混淆 |
| 卡片/表面 | `#ffffff` | 用于表格、表单、详情和摘要容器；不为每个字段单独包卡片 |
| 主文字 | `#17202c` | 标题、关键字段和主要操作文字 |
| 次要文字 | `#5f6b7a` | 说明、时间、辅助字段；不能用于关键提示 |
| 边框 | `#d9e0e8` | 结构边界；弱边框使用 `#e7edf3` |
| 主色 | `#2f6f8f` | 当前导航、主要链接和主要操作 |
| 强调主色 | `#1e5875` | hover、focus 或高优先级操作，不能大面积铺色 |
| 成功 | `#2f6b4f` | 已保存、已通过、已完成；同时配文字 |
| 警告 | `#a16207` | 临近截止、待处理、风险提示 |
| 错误 | `#b42318` | 校验失败、动作失败、越权或危险操作 |
| 圆角 | 6px/8px 为主 | 表面和控件使用分级圆角，不统一使用大圆角 |
| 间距 | 4px/8px 基础 | 页面区块 24px，字段组 16px，控件内部 8px 起步 |

字体候选：推荐使用 `Source Sans 3` 作为界面和正文，使用 `IBM Plex Mono` 仅表达编号、申请号、登记号等需要等宽对齐的标识。字体是否引入、采用 CDN 还是本地资源，须在实现前结合部署限制确认；本 Step 不修改字体加载配置。

信息层级候选：页面标题 24px、区块标题 16px、正文 14px、辅助文字 12px；表格数字使用等宽数字或 `tabular-nums`。这些是设计验收起点，不是要求所有现有页面立即改成完全一致。

响应式候选：沿用当前 `960px` 和 `640px` 两个主要断点；桌面保留侧栏，平板压缩侧栏和内容网格，移动端采用横向导航、单列表单和受控的表格横向滚动。移动端不能依赖浏览器缩放完成核心操作。

动效候选：minimal-functional，仅用于抽屉、状态变化、加载和成功反馈；短过渡 150-250ms，避免长动画干扰审批和录入。

### 五个核心界面规格

#### 1. 工作台

- 目标：让用户在首屏知道待处理事项、临近风险和最短下一步。
- 结构：身份区/页面标题 → 待办与风险摘要 → 最近成果或任务 → 快捷入口；统计卡片数量控制在能支持决策的范围内。
- 关键状态：正常数据、无待办、服务不可用、权限范围为空、加载中、数据刷新失败。
- 验收重点：不能显示已经过期的“计划确认后再实现”文案；每个摘要入口必须进入真实存在的页面或明确标记为未实现。

#### 2. 成果列表

- 目标：按权限快速找到、筛选和进入成果详情。
- 结构：标题和创建入口 → 搜索/类型/状态/密级/部门/时间筛选 → 结果总数和排序 → 表格或窄屏卡片 → 分页/加载更多。
- 关键字段：成果名称、类型、所属部门、责任人、密级、流程状态、关键日期、最近更新。
- 关键状态：首次加载、正常数据、无数据、筛选无结果、接口失败、无权限、长文本、表格横向滚动。
- 验收重点：权限过滤必须在 UI 和 API 两侧成立；密级和附件权限不能只靠隐藏按钮表达。

#### 3. 成果详情与编辑

- 目标：读清成果全貌，并能安全地保存草稿或提交审批。
- 结构：返回和面包屑 → 基本信息 → 类型专属信息 → 密级与权限 → 附件 → 流程时间线/审计摘要 → 操作区。
- 操作分层：保存草稿、提交审批、取消/返回、需要确认的危险动作必须视觉和语义区分。
- 关键状态：只读、可编辑、字段校验失败、保存中、保存失败、保存成功、提交成功、无权查看附件。
- 验收重点：刷新后草稿和提交状态可解释；失败重试不能造成重复提交；错误提示不显示完整异常堆栈。

#### 4. 审批任务

- 目标：让审批人知道审什么、依据什么、可以做什么，以及动作完成后发生什么。
- 结构：任务筛选/状态 → 任务列表 → 详情抽屉或详情区 → 成果摘要和风险提示 → 意见输入 → 允许动作。
- 关键状态：待处理、已处理、无任务、权限不足、动作校验失败、提交中、动作成功、动作失败。
- 验收重点：动作按钮按角色和任务状态显示；审批意见和状态变化同时反馈；不允许通过前端隐藏绕过服务端权限。

#### 5. 系统配置

- 目标：让系统管理员在明确边界内查看配置、导入历史、适配器状态和操作结果。
- 结构：配置分组导航 → 当前配置摘要 → 表单或只读详情 → 保存/测试连接/查看历史 → 风险提示。
- 关键状态：只读、可编辑、配置校验失败、保存中、保存成功、外部适配器不可用、导入失败、权限不足。
- 验收重点：不展示 Token、密码、Cookie、私钥或完整连接串；敏感值只显示脱敏摘要或状态；生产外部系统未接入时明确显示 mock/未配置边界。

### 其他页面的继承规则

成果详情、列表和状态规则作为通用模式，应用到费用、提醒、检索、看板、报表、审计、涉密授权、账号管理和部门管理。各页面可以有不同的业务字段，但不能重新发明加载、空数据、失败、权限不足、成功反馈和移动端表格行为。

### Step 3 浏览器验收标准

Step 3 必须对照本节规格逐项记录“操作步骤、预期、实际、尺寸、证据、结论和问题编号”。至少覆盖 `1440 × 900`、`1024 × 768`、`390 × 844`；没有 API/数据库运行条件时，只能记录环境阻塞，不能把服务不可用页面判定为正常业务流程通过。视觉检查和行为检查分开记录，截图不能替代真实操作。
