## 用户目标

科研人员可以创建一条成果草稿，保存后刷新页面仍能找回，在权限范围外无法查看，并将草稿提交为待院系审核状态，审批任务和审计记录能够证明状态变化。

## 业务价值

建立第一个可真实操作、可持久化、可验证权限边界和审批状态的用户价值闭环，作为后续功能迭代的流程样板。

## 输入与输出

输入：

- 科研人员身份和所属部门；
- 成果类型及创建表单所需的最小合法字段；
- 可复现的本地测试数据和权限矩阵。

输出：

- 一条状态为 `DRAFT` 的持久化成果；
- 刷新或重新打开后可查询到的成果详情；
- 提交后成果状态为 `PENDING_DEPARTMENT_REVIEW`；
- 一个活动审批实例、待处理审批任务和 `SUBMIT` 审计动作；
- 越权访问被 API 和 UI 同时拒绝。

## 数据影响

- 主要实体：`Achievement`、成果类型详情实体、贡献者（仅在最小字段需要时）、`WorkflowInstance`、`WorkflowTask`、`WorkflowAction`、`AuditLog`；
- 保存草稿必须可重复编辑，不得因刷新丢失；
- 提交审批必须在业务允许的事务边界内完成成果状态、工作流和审计记录的一致变化；
- 重复点击提交或重试不能创建重复的活动审批闭环；
- 回滚：本地测试数据可重置或使用事务回滚；不得触碰生产数据。

## 权限与安全边界

- 科研人员可以创建和修改自己的 `DRAFT` 成果，并提交自己的草稿；
- 科研人员不得读取或修改其他用户不在其数据范围内的成果；
- API 必须独立执行身份、角色、部门范围和资源归属检查，不能只依赖前端隐藏按钮；
- 提交后草稿不能继续按草稿规则任意编辑；
- 详情、审计和错误提示不得暴露密码、Token、Cookie、私钥、连接串、完整堆栈或未脱敏敏感字段；
- 涉密字段和附件访问沿用现有授权边界；本任务不扩大涉密权限。

## UI 与交互状态

- 页面入口：成果管理 → 创建成果、成果列表、成果详情/编辑；审批任务页面用于确认提交结果；
- 正常：创建表单可填写，保存后显示草稿状态和可继续编辑入口；
- loading：初次加载、读取详情、保存和提交均有明确进行中反馈；
- empty：没有成果时说明原因，并提供创建入口；
- error：保存、读取或提交失败时显示可理解原因和安全重试入口；
- permission denied：无权查看或修改时显示权限提示，不泄露资源细节；
- disabled：非草稿状态禁用草稿编辑和重复提交；
- submitting：提交期间防止重复点击，并保留用户输入；
- success：保存成功显示草稿状态，提交成功显示待院系审核和审批入口；
- 响应式：至少覆盖 `1440 × 900`、`1024 × 768`、`390 × 844`，移动端不得依赖缩放完成核心操作；
- 可访问性：表单标签、错误关联、键盘焦点、按钮语义和状态文本必须可理解。

## 验收标准

1. Given 科研人员处于成果管理页面，when 打开创建表单并填写最小合法字段，then 表单显示清晰字段、校验规则和保存草稿操作。
2. Given 表单存在缺失或非法字段，when 尝试保存或提交，then 客户端和 API 均拒绝请求，错误与字段关联，不产生半成品审批记录。
3. Given 科研人员提交合法草稿，when 保存草稿，then API 返回成果标识和 `DRAFT` 状态，页面显示保存成功。
4. Given 草稿已保存，when 刷新页面或重新打开成果详情，then 仍能从持久化数据读取相同成果，并保持可编辑状态。
5. Given 其他用户或不在授权范围的用户，when 直接请求成果详情、编辑或提交接口，then API 返回明确的 401/403/404 结果，不泄露成果数据。
6. Given 当前用户拥有自己的 `DRAFT` 成果，when 提交审批，then 成果变为 `PENDING_DEPARTMENT_REVIEW`，生成活动工作流和待处理院系审核任务。
7. Given 提交请求正在处理或已成功，when 用户重复点击或重试，then 不创建重复活动工作流、重复任务或重复提交动作。
8. Given 提交审批成功，when 查看成果状态、审批任务和审计记录，then 三处都能解释同一状态变化，且敏感字段已脱敏。
9. Given 页面运行在桌面、平板和移动尺寸，when 完成创建、保存、刷新和提交操作，then 关键控件可见、可操作，无页面级横向溢出或遮挡。
