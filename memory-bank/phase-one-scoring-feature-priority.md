# Phase One Scoring Feature Priority

日期：2026-07-05

范围：Step 82B docs-only。本文基于原始需求完成度矩阵、一期产品目标、当前架构能力边界和下一阶段路线，按考核/竞赛评分视角整理一期未完成功能的优先级方案。

## 结论

当前后续路线应优先补齐“评审能看见、能演示、能验收”的功能闭环，而不是优先投入 production/VPS/真实外部系统联调。

原因：

- 一期核心业务骨架已基本建成，评分短板主要在可展示闭环、验收脚本和二期亮点 MVP，而不是生产部署执行。
- 原始需求中完整财务系统深度对接、真实 HR/SSO、真实邮件/短信、真实 DOI/专利状态联调、运维监控大盘、灾备演练和十万级真实压测均属于明确延后、部署阶段或二期深化范围。
- mock/adapter 可以用于展示系统具备可替换集成边界和降级能力，但只能表述为演示能力，不能表述成真实外部系统联调。
- 本地 synthetic acceptance 可以证明本地功能路径和边界条件，但不等于 production acceptance；不能替代生产环境授权、生产数据、真实外部系统、运维窗口和生产证据。

## 不优先路线

当前不优先做以下事项：

- production/VPS 部署执行。
- 生产 DB、生产 migration、生产 runbook 执行。
- 真实 HR/SSO、真实财务、真实邮件/短信、真实 DOI/文献库、真实专利状态联调。
- 十万级真实压测、灾备演练、生产监控大盘。

这些事项仍然重要，但它们属于部署授权、生产安全、运维或二期集成专项。它们需要单独的生产授权、证据边界、脱敏策略、回滚计划和人工确认；不适合作为当前评分导向的第一优先级。

## 表述边界

- mock/adapter：只能表述为“演示集成边界、降级策略、调用日志和可替换设计”，不能表述为“已完成真实外部系统联调”。
- 本地 synthetic acceptance：只能表述为“本地演示/测试验收通过”，不能表述为“生产验收通过”。
- runbook 文档：只能表述为“已有执行准备或操作说明”，不能表述为“runbook 已在生产执行”。
- schema/migration 文件：只能表述为“本地代码和迁移文件存在”，不能表述为“生产 migration 已应用”。
- 导入本地 apply：只能表述为“本地 synthetic 数据闭环”，不能表述为“真实生产数据导入已授权或已执行”。

## Step 83 建议起点

Step 83 应聚焦“费用线上审批闭环”的最小可演示闭环：

- 科研秘书或费用管理员创建/维护费用记录。
- 发起费用处理或审批动作。
- 审批角色可查看待办、通过/驳回并留下意见。
- 费用状态、提醒、凭证附件和审计日志联动更新。
- Web 端能按角色展示申请、审批、结果和历史。
- 验收仅限本地/演示环境，不接真实财务系统，不访问 production/VPS，不执行真实付款或外部系统调用。
