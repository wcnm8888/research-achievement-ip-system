# Feature Brief - 一期基础刚需版

## 标题

科研成果与知识产权管理系统一期基础刚需版。

## 背景

- 为什么要做：研究院需要从 Excel 台账升级为可审批、可追踪、可统计、可审计的成果与知识产权管理系统。
- 当前痛点：成果底数不清、费用逾期风险高、数据汇总耗时、附件和审批留痕不足、跨系统重复录入。
- 用户/业务场景：科研人员登记成果，部门科研秘书审核和管理费用，系统管理员归档和配置，领导查看统计，审计人员查阅日志。

## 目标

- 主要目标：交付一个可运行的一期系统，覆盖论文、专利、软著登记，基础审批，部门隔离，费用台账，基础预警，基础搜索，看板，附件和审计。
- 次要目标：为 DOI 自动补全、邮件通知、HR/SSO、财务、专利状态同步等外部接口建立 adapter 契约。
- 成功标准：一期用户流程可闭环，权限不越界，核心写操作可审计，费用预警可追踪，搜索和看板可用。

## 非目标

- 本次明确不做：完整移动端、真实短信接口、完整财务系统深度对接、复杂自定义报表引擎、完整成果转化闭环、十万级真实压测。
- 延后处理：成果转化、收益分配、引文分析、真实专利状态同步、真实 HR/SSO、真实外部邮件联调、运维监控大盘、灾备演练。

## 用户流程

1. 科研人员登录系统，进入成果登记，选择论文、专利或软著。
2. 用户填写基础字段、专属字段、作者/发明人/著作权人、密级、所属部门和附件。
3. 系统进行必填校验、唯一性校验和权限校验。
4. 用户保存草稿或提交审批。
5. 部门科研秘书查看本部门待办，初审通过或驳回。
6. 系统管理员对通过初审的成果进行归档。
7. 系统对新增、修改、提交、审批、归档、附件上传/下载记录审计日志。
8. 专利/软著费用进入费用台账，系统根据截止日期生成预警任务。
9. 授权用户通过检索和看板查看权限范围内成果数据。

## 输入与输出

- 输入：成果表单、附件、审批意见、费用记录、预警规则、角色和部门配置、搜索条件。
- 输出：成果台账、审批状态、附件元数据、费用预警、站内通知、搜索结果、统计看板、审计日志。
- 关键状态：草稿、待部门审核、部门驳回、待归档、已归档、已作废、费用待缴、费用已缴、费用逾期、提醒待发送、提醒已确认。

## 约束

- 技术约束：核心业务逻辑不得直接依赖 UI、数据库 ORM、外部 API 或对象存储 SDK；外部能力必须通过 adapter 隔离。
- 时间/成本约束：一期优先实现基础刚需，不实现复杂可配置审批设计器和完整报表引擎。
- 安全/隐私约束：不在代码、文档或日志中记录密钥、Token、密码、Cookie、证书和私钥；附件下载必须后端鉴权。
- 兼容性约束：优先适配 Chrome、Edge、360 浏览器和 Windows/macOS 桌面端。

## 风险

- 产品风险：如果一期范围继续扩大，会拖慢核心台账、审批、费用预警交付。
- 技术风险：权限和数据隔离如果散落在各接口中，容易出现越权漏洞。
- 数据风险：DOI、申请号、登记号等唯一业务键不明确会造成重复登记。
- 体验风险：成果字段多，表单需要分组、草稿和错误提示，否则录入成本高。

## 待确认问题

1. 一期是否需要接入真实统一身份认证，还是先使用本地账号体系并预留 SSO adapter。
2. 涉密附件一期是否只做权限隔离和存储加密预留，还是要求实际加密落地。
3. 一期演示数据规模采用多少条：建议至少 1 万条成果种子数据用于基础检索验证。
