# Step174 - 认证性能复跑边界与最终验收覆盖矩阵

## 目标

在 Step170A-D、Step172、Step173 之后，整理本地评审提交版的最终验收口径：

- 明确哪些能力已完成。
- 明确哪些能力是本地 MVP / 部分完成。
- 明确哪些能力仍属于二期或生产化待接入。
- 明确性能验收的认证复跑状态，避免把本地基线说成生产压测完成。

本文件服务于“研究院科研成果与知识产权管理系统一期本地评审提交版 / local-demo / local Docker production-like”。不代表真实生产上线完成、真实外部系统联调完成或 VPS/生产 DB 验收完成。

## 认证性能复跑状态

已有脚本：

- `scripts/local-performance-baseline-step170d.mjs`

脚本能力：

- 支持默认本地 demo header。
- 支持通过临时环境变量 `LOCAL_PERF_EMAIL` / `LOCAL_PERF_PASSWORD` 获取本地 session cookie。
- 报告写入 `.local-step170d-performance/`，该目录为本地产物，不提交。
- 脚本只做短时 GET 基线和 50 并发轻量预演，不做破坏性压测、不写业务数据。

当前 Step174 状态：

- 已检查当前会话环境变量存在性：`LOCAL_PERF_EMAIL` 缺失，`LOCAL_PERF_PASSWORD` 缺失。
- 因缺少用户现场提供的临时本地认证凭据，本 Step 未执行认证后性能复跑。
- 不读取 `.env` / `.env.production`，不读取浏览器 Cookie，不读取或回显密码，不绕过认证。

可对外说明：

> 本地性能基线脚本已具备，并已支持认证参数；普通入口和非认证基线已有历史证据。认证后的业务接口复跑需要现场提供临时本地账号凭据后执行，不能把当前状态表述为生产性能验收完成。

不可对外说明：

> 已完成 10000 条正式压测、真实 50 用户业务并发验收、生产性能验收或 VPS/生产 DB 性能验收。

建议说：

> 当前版本是一期本地评审提交版，核心业务链路、权限、审计、提醒、报表、备份验收、接口预留和演示错误态已经形成可演示闭环。外部 DOI、真实邮件、HR/SSO、财务、专利服务商、生产备份恢复和正式压测均按生产化待接入口径管理。

> 系统已经真实上线、已完成所有外部系统联调、已完成 VPS/生产数据库验收、已完成生产级 50 用户并发或 10000 条压测。
